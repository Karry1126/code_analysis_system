# lvl 活动命令字流程整理

lvl（AVA 军团对战）活动由 **Celery beat 定时扫描排期 → 生成异步任务 → worker 执行** 三段式驱动。仓库里存在 **v1（旧）** 和 **v2（新）** 两套并行实现。

## 一、整体链路

    ```

lvl_event_schedule.json (排期)  ──┐
lvl_event_proj.json     (方案)  ──┤→ beat 扫描 → celery_task 表 → worker 执行 → lvl_schedule(_v2) 表状态流转
lvl_sign_data.json      (报名)  ──┘

    ```

## 二、v1 流程（`lvl_task.py` + `lvl_worker.py`）

**Beat 侧** `LVLTask.GetTask`（lvl_task.py:16-73）
- 读 `../conf/module_conf.json` 拿 `path`，加载 `lvl_event_schedule.json` 的 `schedule`。
- 遍历每条排期，取 `match_time`（begin）、`battle_time`（close）；`cnt_time >= close_time` 则跳过。
- 为每个 `event_id` 生成一个 `try_match` 任务（`begin_time=match_time`，`plan_time=match_time+300`，`end_time=battle_time`）。
- 同时把 `timezone_list` 转成 `{timezone_id: [battle_btime, battle_etime]}` 写入 `business_data`。

**GenTask**（lvl_task.py:75-90）
- 计算 `countdown = begin_time - now + 30`，不足 60 秒则强制 60（避免多线程 bug）。
- `task_name == "try_match"` → `lvl_do_match.apply_async(...)` 投递到 `module_conf["request_conf"]["queue"]`。

**Worker 侧** `lvl_do_match`（lvl_worker.py:31-56）
- 加载 `module_conf` 与排期文件，然后顺序执行 5 个阶段：
  1. `try_do_match()` — 匹配
  2. `try_assign_battle_sid()` — 分配战斗 sid
  3. `try_init_battle_sid()` — 初始化战斗 sid
  4. `try_release_match_result()` — 释放匹配结果
  5. `try_send_mail()` — 发邮件
- 另有 `check_error()`：匹配开始 5 分钟仍未完成（`status != 10 且 != -1`）则钉钉告警，非 online 环境标记 `status=-1`。

**数据表**：`lvl_schedule`（InitData/ClearData，lvl_task.py:92-104）。

## 三、v2 流程（`lvl_task_v2.py` + `lvl_worker_v2.py`）

**Beat 侧** `LVLTaskV2.GetTask`（lvl_task_v2.py:17-131）
- 用 `tools.get_config("path")` 读排期，为每个 `event_id` 生成 **5 类任务**：
  | task_name | 触发时间 | 说明 |
  |---|---|---|
  | `do_auto_match` | match_time | 自动匹配 |
  | `release_schedule` | manual_time | 释放排期 |
  | `update_battle_result` | end_time | 更新战斗结果 |
  | `lvl_al_assistant_task` | forecast_time-300 | 助手请求 |
  | `lvl_al_assistant_battle_time_task` | match_time | 助手战斗时间请求 |
- 若 `cur_time > max(end_time)`，删除该 event 的任务与 business_data。

**GenTask**（lvl_task_v2.py:133-166）按 `task_name` 分发到 worker：
- `do_auto_match` → `lvl_do_auto_match`
- `release_schedule` → `lvl_release_schedule_work`
- `update_battle_result` → `lvl_update_battle_result`
- `lvl_al_assistant_task` → `send_al_assistant_request`
- `lvl_al_assistant_battle_time_task` → `send_al_assistant_battle_time_request`
- 未知 task_name 记 error。

**心跳任务** `GetHeartbeatTask`（lvl_task_v2.py:180-208）
- 固定生成 `do_hand_match`（手动匹配，每 300s）。
- 非 online 环境额外生成 `do_web_match`。
- `GenHeartbeatTask` 分发：`do_hand_match` → `lvl_do_hand_match_work`；`do_web_match` → `lvl_do_web_match`。

**Worker 侧** `lvl_do_auto_match`（lvl_worker_v2.py:71-160）主流程：
1. 读 `lvl_event_schedule.json` + `lvl_event_proj.json`。
2. `GetScheduleForFile` 校验排期文件中有该 event_id（否则 task_status=3 + 钉钉）。
3. `GetScheduleForMysql` 校验 `lvl_schedule_v2` 表中有该 event_id。
4. 从 proj 取 `match_rule`、`battle_user_num`；proj 无该 pid 则 task_status=3。
5. 拉 S3 报名文件 `lvl_sign_data.json`，无该 event_id 则 task_status=4。
6. `change_schedule_status(event_id, 1)` 标记匹配中。
7. `init_sign_data` → `get_data_from_server`（失败 task_status=3）→ `get_match_score` → `send_sign_mail`。
8. `get_battle_history` → `do_real_match` → `change_schedule_status(event_id, 2)`，task_status=2。

**手动匹配** `lvl_do_hand_match_work` → `ResetMatch`（lvl_worker_v2.py:161-200）
- 查 `lvl_schedule_v2` 中 `status IN (2)` 的排期。
- 检查 S3 上 `{event_id}` 目录是否有手动匹配文件 + flag（`s3cmd ls | wc -l == 2`）。
- 有则下载 `{event_id}_manual.xlsx`、删除 `.ok` flag、读「匹配结果」sheet 预处理。

**数据表**：`lvl_schedule_v2`（InitData/ClearData，lvl_task_v2.py:168-178）。

## 二、处理对象与三段式流程

以 `get_al_rank` 为例，处理类为 `CProcessGetAlRank`（`command_process.h:13-25`），继承 `CProcessBase` + `CSingleton`，实现四个方法：


| 方法                 | 作用              |
| ------------------ | --------------- |
| `HandleProcedure`  | 流程总调度（状态机）      |
| `ProcessCmdBefore` | 请求前处理：参数校验、数据准备 |
| `GetData`          | 向下游请求数据         |
| `ProcessCmd`       | 处理命令字、落库        |


**状态机调度**（`command_process.cpp:8-84`）按 `session->m_procedure_cmd` 顺序推进：

1. `EN_PROCEDURE__START` → 调 `ProcessCmdBefore`（`command_process.cpp:86-91`，当前仅置 `is_finish=TRUE` 直接通过）；失败置 `EN_RET_CODE__D1__PROCESS_CMD_BEFORE_ERROR`，成功后切到 `EN_PROCEDURE__GET_DATA`。
2. `EN_PROCEDURE__GET_DATA` → 调 `GetData`（`command_process.cpp:93-136`），内部再按 `m_procedure_func` 走 `START → REQUEST → RESPONSE → END`：
  - `REQUEST`：`CSyncProcessMgr::SendRankPlayerReq(session)` 发下游请求；
  - `RESPONSE`：接收下游响应（`RecvRankPlayerRsp` 当前被注释）；
  - 失败置 `EN_RET_CODE__D1__GET_DATA_ERROR`，成功后切到 `EN_PROCEDURE__PROCESS_CMD`。
3. `EN_PROCEDURE__PROCESS_CMD` → 调 `ProcessCmd`（`command_process.cpp:138-185`）：
  - 从 `session->m_jsn_param["event_id"]` 取活动 ID；
  - 解析 `m_rsp_content` 为 JSON，校验 `event_id` 是否存在于 `CEventScheduleConf::m_schedules`；
  - 取 `disappear_time`，遍历 `response.svr_multi_alliance_rank_inside` 各 `sid` 的 `rank_list`；
  - 对每个 `aid` 用 `CEventUtils::GetTopAlHashKey(event_id, sid)` 取 hash key，写入 `ExtraDataNode`（`force_rank`/`al_flag`/`al_nick`/`al_name`/`ksid`），再 `SetNodeUpdateRelease` 落库；
  - 同时用 `GetTopAlSvrHashKey(event_id)` 更新服务维度节点；
  - 失败置 `EN_RET_CODE__D1__PROCESS_CMD_ERROR`，成功后切到 `EN_PROCEDURE__END`。
4. `EN_PROCEDURE__END` → `is_finish = TRUE`，流程结束。
